# DaVinci 网关路由工具 1.2.0

新增 `DoIP_to_CAN` 七列映射执行支持。物理寻址配置请求转发和 CAN 响应回转；功能寻址只配置请求，一个 Tester 与逻辑地址组合的多个 CAN 目标共用 Channel、Rx PDU 和 PduR 请求路径。按真实引用复用已有配置，并保留已有请求路径中的本机 Dcm、LIN 等目标。

CAN 前置必须完整。同一事务内明确提交的 CAN 诊断变更先执行，DoIP 映射随后读取真实引用。DoIP 表不会自动创建缺失 CAN 配置。前置缺失时列出每条映射，默认停止；用户选择 BLOCK 或 SKIP 后重新预览。SKIP 报告全部跳过项，物理请求与响应作为完整映射处理。GUI、MCP、CLI 与公共 Facade 传递同一次选择，只有有效预览可生成。

新增 Channel、TargetAddress、EcuC PDU、PduRRoutingPath 使用 `GWT_`。Channel 内 Rx/Tx 子容器及 PduR Source/Destination 保留业务、地址、网段、方向可区分的短名，不加主对象前缀。既有对象名称保持原样，新增名称、ID、UUID 和内部引用在写出前检查。

本次基准约定使用同一 Tester 的 logicalAddress=0x0003 物理样例、0xE400 功能样例，通过 Tester 与 TargetAddress 引用识别。Channel 缓冲参数、通知、EcuC 长度、PduR 参数均取相应样例；缺少或冲突时停止并要求指定来源。ID 从现有完整定义作用域分配未占用值。已有完整配置复用并保留其参数。

DoIP 请求直接复用对应 CAN Tx PDU 关联路径的 Queue，物理响应追加到对应 CAN Rx Source 的已有路径并复用其 Queue。QueueDepth、TpThreshold、SharedBuffer 与 BufferRef 不修改，不为 Tester 新建 Queue。关联目标的 Queue 冲突时阻断。使用 API_FORWARDING 且无 Queue 的本机目标不参与共享 Queue 检查。

没有信号更新时允许基准缺少 Com；有信号执行行时仍要求 Com。输入和客户基准保持只读，输出通过内部引用、对象语义和共享队列复核后原子写出。工具校验不代表已运行 DaVinci Validate/Generate。
