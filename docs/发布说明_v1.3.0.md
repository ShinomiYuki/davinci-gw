# DaVinci 网关路由工具 1.3.0

新增本地 Bridge 服务。Bridge 在内部端口上提供 MCP 端点，把客户端请求转发到可独立配置的核心，桌面客户端不再随安装包携带核心代码。

Bridge 只做令牌校验与转发，不新增路由规则，也不改变现有 MCP 服务的边界。对外仅暴露 `get_gateway_capabilities`、`validate_gateway_inputs`、`preview_gateway_update`、`generate_gateway_arxml` 四个网关工具，参数与语义和 STDIO 服务一致。自动修复与诊断系列不在 Bridge 上开放：这些工具会按调用方传入的仓库路径与解释器路径启动子进程，放到监听端口上等于允许远程驱动本机命令，需要时继续使用 STDIO 服务。

核心有三种形态，由部署方单独配置：进程内核心、独立 STDIO 子进程、内网 HTTP 服务。核心可单独升级，客户端无需重新分发。Bridge 默认只监听回环地址，所有请求校验 Bearer 令牌，并启用 DNS 重绑定防护；确需对外监听时必须显式开启。启动后写出客户端发现文件，记录端口、端点、令牌与核心形态，客户端按标准 MCP 协议连接即可，不需要了解 Bridge 内部实现。

自动修复协调器改为按需导入：只使用生成流程的部署不再需要安装 Codex 依赖；`RepairContractError` 移到无外部依赖的模型模块，错误语义保持不变。生成、预览、校验的输入输出契约与既有版本一致，路由规则、Excel 输入契约与 ARXML 处理逻辑没有变化。

Bridge 目前只提供源码运行入口，尚未纳入 `packaging/` 免安装包与 `scripts/setup.ps1` 安装流程；同事端使用的 GUI 免安装包仍是原有形态。本次发布同时提供 GUI 与 MCP Windows x64 ZIP。

版本标签为 `v1.3.0`。GUI、MCP、核心及 Windows 版本资源统一为 1.3.0，GitHub Release 提供 GUI、MCP Windows x64 ZIP 和对应校验文件。公司镜像同步提交和标签，二进制以 GitHub Release 为准。

验证使用人工构造的工作簿和 ARXML，覆盖配置校验、工具转发与结果解析、令牌鉴权、核心故障隔离，以及进程内核心与独立 STDIO 核心两种形态的端到端调用。未修改客户配置，也未执行 DaVinci 的实际 Validate/Generate。
