# DaVinci 网关路由工具 1.3.0

新增 OTA 白名单配置能力，提供核心接口、命令行、MCP 和桌面入口。读取基准 ARXML 后先检查缺漏，再预览对象和引用的精确变更；取得用户确认后生成新的 ARXML。输入保持只读，禁止覆盖基准或已有输出。

## 配置范围

目标为 BD、CH、DA、DK、DM、EP、GL、IC、LC、PT、SU，共 11 个 CAN 网段。每网段配置 RX、TX 两个 Com OTA 组及对应 BswM 关闭动作、专用动作列表、三层表达式和规则，总计 22 套；每网段增加或复用一套网络管理（NM）组合控制，共 11 套。不配置 DG、LIN 或以太网，也不新增软件组件或模式入口。

工具保留所有具体报文的 `ComIPduGroupRef`，由用户手动移除白名单报文的普通组引用，并关联同网段、同方向的 OTA 组。工具建立 BswM 对 OTA 组的引用，空组也会建立控制链。

标准禁收发列表只移除关闭对应 OTA 组的动作项，保留独立动作、普通组关闭项、OTA 启用项、接收超时监控和其他控制。诊断底层各方向使用四个精确状态的等于比较，通过 OR 组合；中间层为“非 OTA AND 诊断禁收发”；外层发送为“不等于完整通信 OR 中间层”，接收为“等于无通信 OR 中间层”。NM 在原有完整禁用表达式外增加非 OTA 条件，保留原有规则的禁用、启用分支和内部条件，不新增 NM_RX。

## 检查、预览与生成

检查识别已有完整配置、缺失项、参数或引用差异和冲突。预览列出新增对象、引用修改、列表项移除及前后值。语义等价的既有配置可复用；关键引用缺失、歧义或冲突会阻止生成，不猜测通道或静默覆盖。只有 Com、BswM 的导出文件可沿已有明确外部引用定位，不要求把未导出的外部模块一概补齐。

生成复用已确认规划，核实基准是否变化，输出后复核控制链。重复执行不重复创建配置。CLI 的 `ota-generate` 在同一进程显示预览并确认；MCP 的 `preview_ota_update` 分页返回精确变更，全部获取后才允许 `generate_ota_arxml`；GUI 通过主窗口“OTA 白名单配置…”打开独立窗口。详见 [GUI 使用说明](GUI.md) 和 [MCP 使用说明](MCP本地安装与使用.md)。

## 验证边界与发布

配置的专用关闭规则没有启用分支。关闭条件消失不表示自动启动组，恢复依赖保留的标准启用规则；NM 启用表示恢复发送能力，不保证网络始终唤醒。先禁收发再切入 OTA、诊断恢复和网络退出后重新进入的启用边界，仍需在目标 DaVinci 工程和实际网络中验证。

本工具的静态检查不能替代 DaVinci Validate/Generate 或硬件测试。本次不宣称已执行客户工程的这些验证。

验证完成 403 项非慢速回归；审查修复后的全部 OTA 定向测试 25 项通过。已执行原生 Codex 审查及复审，发现的问题均已修复并验证。测试覆盖收发组分离、精确动作移除、混合动作保护、取消、输入变化、禁止覆盖、幂等以及静态恢复边界。

核心、GUI、MCP、Windows 版本资源和构建默认版本统一为 1.3.0，正式标签为 `v1.3.0`。GitHub Release 提供 GUI、MCP Windows x64 ZIP 和对应校验文件；公司镜像同步发布提交和标签，二进制以 GitHub Release 为准。客户 ARXML、工作簿、截图及本地开发记录不进入发布内容。
