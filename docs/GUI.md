# DaVinci 网关路由桌面工具使用说明

## 启动

将 `davinci-gw-gui-0.3.6-win-x64.zip` 完整解压到本地目录，双击 `davinci-gw-gui.exe`。程序是免安装 Windows x64 桌面应用，不需要 Python、PATH 或网络连接。不要只从压缩包中单独拖出 EXE；同目录的 `_internal` 是运行所需文件。

安装目录可以只读。窗口位置和最近浏览目录保存在当前 Windows 用户设置中，日志位于 `%LOCALAPPDATA%\DaVinciGW\logs\gui.log`；不会把配置表内容、ARXML 内容或完整问题列表写入日志。

## 四步工作流

1. 选择或拖入标准配置表。文件必须是 `*_vX.x.xlsx`，并符合本项目输入契约。
2. 选择或拖入完整基准 ARXML。文件必须包含 CanIf、Com、EcuC、PduR 必要模块。
3. 点击“预览变更”。界面会显示文件大小、Schema、目标版本、模块状态、动态功能统计以及问题/保留决定。预览不写输出文件。
4. 确认输出路径后点击“生成 ARXML”。输出必须是新的 `.arxml` 文件，不能与基准相同，也不能覆盖已有文件。

预览成功后，程序持有一份当前进程内的 Prepared Session。生成会复用这份已解析、已规划的内存工作树，不再重新解析基准 ARXML。只要修改配置表路径或基准路径，旧预览立即失效，必须重新预览。

直接报文路由继续使用标准 18 列表，不需要填写路由组。预览时工具会根据目标 CAN 通道、TxBuffer 和基准 ARXML 的真实成员引用自动识别唯一应用路由组；找不到、歧义、实际归组异常或误指向诊断组时会阻止生成，并在问题中显示工作表行、源/目标报文名称、CAN ID、通道、组名和对象完整路径。

既有直接报文路由通过真实引用链识别，不要求对象名以 `Gw`、`GWT` 或 `GWH` 开头，也不会因为旧名称不同再创建一套路由。只有位于精确源 RoutingPath 下、引用唯一目标 EcuC PDU 的 DestPdu 才算既有网关路由；同名同 ID 的本地自发 Tx 不会被当成路由。若只发现本地端点、部分链或两条完整重复链，问题界面会列出候选完整路径并阻止生成，避免继续污染基线。

新增信号路由时，工具会把实际参与 Mapping 的源端 Rx 和目标端 Tx `Signal Access` 自动设置为 `ACCESS_NEEDED_BY_SWC_OR_COM`。上一版已经生成 Mapping、但信号仍显示 `ACCESS_UNCLEAR` 时，可以使用同一配置重新生成补齐，无需在 DaVinci 中逐个修改。

## 阅读结果

- “错误”会阻止生成，请按说明、工作表和行号修正输入。
- “警告”表示工具可以继续，但应确认业务含义。
- “保留决定”是删除过程中为保护共享对象、人工配置或证据不足的超时参数而作出的非阻塞决定。
- “路由组非主成员”是基线 ARXML 一致性警告，每个异常成员只显示一次，位置指向基线文件，不归到当前 Excel 行。处理建议是核对基线路由组成员；工具不会自动迁移。
- 变更摘要卡片按核心返回的功能动态生成，不代表只支持固定的两类卡片。
- 摘要卡片出现“查看详情”时，可以打开独立窗口查看本次实际计划新增、删除的报文或信号路由；已存在、未找到、冲突和跳过项不会冒充为实际变更。

问题表包含“报文 ID”和“报文名称”两列，并区分源端与目标端；同时支持按级别筛选、全文搜索、表头排序和复制所选行。直接报文路由表本身携带 CAN ID，因此可同时显示 ID 和名称；标准信号路由表不携带 CAN ID，相关问题只显示可证明的源/目标报文名称，ID 显示为“—”，不会从项目特定映射中猜测。高级信息中可查看操作 ID、Prepared Session ID、版本和日志目录。

例如“本次仅删除指定目标信号；删除后该源信号仍路由到另外 2 个目标信号，因此保留 Mapping、Source 和源端超时”表示该源信号原本有多个目标，本次目标已删除，但另外两个目标仍在使用同一源端链，所以共享的 Mapping、Source 和超时配置不能一起删除。

## 取消和关闭

预览或生成期间可以点击“取消”。取消是协作式的：程序会等待下一个安全边界，因此大文件写临时文件期间可能不会立即结束。原子发布前取消会清理临时文件且不生成目标；如果原子发布已完成，结果仍会报告成功，避免把已发布文件误报为取消。

任务运行时关闭窗口，程序只询问一次是否取消并退出。确认后窗口会等待工作线程安全收尾，不会强制终止线程。

## 常见问题

- “输出文件已存在”：选择一个新文件名。程序不覆盖现有输出。
- “预览后输入发生变化”：配置表或基准的大小、修改时间或内容摘要发生变化，请重新预览。
- “Prepared Session 不可提交”：预览已失效、被消费或过期，请重新预览。
- “未解析到应用路由组、主通道歧义、成员重复/悬空或删除后为空”：按问题中的报文名称、CAN ID、通道、组名和 DestPdu 路径修正引用数据或 DaVinci 工程后重新预览。
- “目标端已被本地发送占用”或“源路由链歧义”：请按问题中的 CanIf、EcuC、PduR 完整路径检查基线。工具不会按名称前缀猜测归属，也不会自动清理历史重复链。
- 信号路由导入后仍显示 `ACCESS_UNCLEAR`：确认使用的是 0.3.4 或更高版本，并用原配置表和未手工覆盖的基线重新预览、生成。
- 程序启动失败或内部失败：打开 `%LOCALAPPDATA%\DaVinciGW\logs\gui.log`，向维护者提供操作时间、版本和异常类型；不要发送涉密输入文件。

## 当前边界

桌面版只编排已有 GatewayFacade，不新增路由规则。当前不支持诊断/CanTp、直接报文 LIN 路由、多 ARXML 合并、DaVinci 自动导入/Validate、云端服务、遥测或自动更新。
