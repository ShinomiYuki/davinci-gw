# DaVinci 网关路由桌面工具使用说明

## DoIP→CAN 前置选择

标准表的 `DoIP_to_CAN` 页参与同一次预览。前置 CAN 诊断配置缺失时，窗口展示 Tester、逻辑地址、CANBus、请求、响应和缺少的引用。A 阻断整个本次生成，B 跳过缺失映射并重新预览，C 返回修改输入。未作选择时无法生成。选择只用于当前输入，文件路径或内容变化后重新判断。成功预览中的“跳过”统计和问题清单保留每条被跳过映射。

## 启动

将 `davinci-gw-gui-<版本>-win-x64.zip` 完整解压到本地目录，双击 `davinci-gw-gui.exe`。程序是免安装 Windows x64 桌面应用，不需要 Python、PATH 或网络连接。不要只从压缩包中单独拖出 EXE；同目录的 `_internal` 是运行所需文件。

安装目录可以只读。窗口位置和最近浏览目录保存在当前 Windows 用户设置中，日志位于 `%LOCALAPPDATA%\DaVinciGW\logs\gui.log`；不会把配置表内容、ARXML 内容或完整问题列表写入日志。

## 界面说明

窗口采用应用壳层结构：**顶部全宽导航栏 + 左侧输入侧栏 + 右侧校验工作台 + 底部全宽状态栏**。顶栏与底栏固定不随内容滚动，左右两栏各自独立滚动。窗口最小尺寸为 1240×700，默认 1440×900；低于该宽度时右栏放不下问题表的五列，「确认状态」列会被挤出视野，因此不再允许继续缩窄。

- **顶部导航栏**：左侧是矢量网关拓扑标识、应用标题、版本号与「本地运行」标识；右侧是「重置演示数据」（开发环境下有示例输入时才显示）与白天 / 夜间主题切换（显示为「浅色 / 深色」，带太阳 / 月亮图标）。
- **左侧输入侧栏（约 470 像素）**：**① 选择输入文件** 用文件槽呈现，表格与 ARXML 使用不同配色区分类型，路径可直接拖入，下方是带信息图标的输入契约说明框；**② 预览并生成** 放置输出路径与三个动作按钮；成功后出现「生成结果」卡片，给出输出路径与「打开所在文件夹」「复制路径」；左栏底部是「本次路由变更统计」卡片，校验通过时右侧显示绿色「校验通过」胶囊。
- **右侧校验工作台**：细网格背景，顶部是流水线状态条，显示当前阶段、三步面包屑（`1. 选择文件 / 2. 预览校验 / 3. 确认生成`，当前步骤高亮）与 `STEP n / 3`；其下是「问题与保留决定」与「输入检查」。问题表按「确认复选框 + 级别胶囊 → 规则代码与报文名副行 → 粗体问题描述与柔和工程建议 → 位置 → 确认状态胶囊」呈现，报文 ID、报文名称与处理建议并入副行，不再单列展示。问题卡片占满右栏剩余空间，表格行高 108 像素，描述（最多两行）与工程建议（最多三行）都能完整显示，问题更多时在表格内部滚动。级别、代码、位置与确认状态四列固定宽度，说明列吃掉剩余宽度：窗口越宽，长描述能显示的字数越多。
- **底部状态条**：操作 ID、会话 ID、版本（含 AUTOSAR 版本号）与日志目录入口，收敛为一行等宽字体信息条。

### 白天与夜间主题

页头的主题切换可在「浅色」和「深色」之间切换，选择会保存在当前 Windows 用户设置中，下次启动沿用。首次启动时默认跟随 Windows 的应用主题。两种主题下卡片、表格、胶囊、图标与状态条配色保持一致，夜间主题只降低亮度，不改变信息层级。

### 单一双栏布局

界面只保留双栏紧凑布局，不再提供原版单栏长条布局的对比切换。页头右侧只有「重置演示数据」与主题切换（浅色 / 深色），开发环境下存在示例输入时才显示前者。

## 人工确认

「问题与保留决定」为警告与保留决定提供人工确认。错误仍会阻止生成；警告与保留决定需要人工核对后勾选确认，可用「批量确认」一次性确认当前可见项（没有待确认项时该按钮置灰）。状态条会提示还有多少项待确认，问题表右侧以「○ 待确认」「✓ 已确认」「✕ 需修复」胶囊呈现每一条的处理状态。

人工确认是**硬门禁**：只要还有未确认的警告或保留决定，「生成 ARXML」按钮保持禁用，按钮下方会给出橙色提示说明还差几项，`Ctrl+G` 快捷键同样被拦截，不会绕过确认直接生成。确认完毕后按钮立即恢复可用，提示消失。

## 四步工作流

1. 选择或拖入标准配置表。文件必须是 `*_vX.x.xlsx`，并符合本项目输入契约；客户常见的版本区间命名 `*_v4.83-4.85.xlsx` 也被接受，此时按区间上限（4.85）作为目标版本，并在问题清单中给出需要人工确认的 `WORKBOOK_VERSION_RANGE` 提示。
2. 选择或拖入基准 ARXML。文件必须包含 CanIf、EcuC、PduR；更新信号路由时还要求 Com。

标准配置表和基准 ARXML 既可以拖到文件槽上，也可以直接拖到路径输入框内，两处都会自动填入并识别类型。
3. 点击“预览变更”。界面会显示文件大小、Schema、目标版本、模块状态、动态功能统计以及问题/保留决定。预览不写输出文件。
4. 确认输出路径后点击“生成 ARXML”。输出必须是新的 `.arxml` 文件，不能与基准相同，也不能覆盖已有文件。

预览成功后，程序持有一份当前进程内的 Prepared Session。生成会复用这份已解析、已规划的内存工作树，不再重新解析基准 ARXML。只要修改配置表路径或基准路径，旧预览立即失效，必须重新预览。

直接报文路由继续使用标准 18 列表，不需要填写路由组。预览时工具会根据目标 CAN 通道、TxBuffer 和基准 ARXML 的真实成员引用自动识别唯一应用路由组；找不到、歧义、实际归组异常或误指向诊断组时会阻止生成，并在问题中显示工作表行、源/目标报文名称、CAN ID、通道、组名和对象完整路径。

既有直接报文路由通过真实引用链识别，不要求对象名以 `Gw`、`GWT` 或 `GWH` 开头，也不会因为旧名称不同再创建一套路由。只有位于精确源 RoutingPath 下、引用唯一目标 EcuC PDU 的 DestPdu 才算既有网关路由；同名同 ID 的本地自发 Tx 不会被当成路由。若只发现本地端点、部分链或两条完整重复链，问题界面会列出候选完整路径并阻止生成，避免继续污染基线。

新增信号路由时，工具会把实际参与 Mapping 的源端 Rx 和目标端 Tx `Signal Access` 自动设置为 `ACCESS_NEEDED_BY_SWC_OR_COM`。上一版已经生成 Mapping、但信号仍显示 `ACCESS_UNCLEAR` 时，可以使用同一配置重新生成补齐，无需在 DaVinci 中逐个修改。

## 阅读结果

- “错误”会阻止生成，请按说明、工作表和行号修正输入；问题表中的级别按语义着色（错误红、警告橙、保留决定紫、提示蓝），便于快速分辨。
- “警告”表示工具可以继续，但应确认业务含义。
- “保留决定”是删除过程中为保护共享对象、人工配置或证据不足的超时参数而作出的非阻塞决定。
- “路由组非主成员”是基线 ARXML 一致性警告，每个异常成员只显示一次，位置指向基线文件，不归到当前 Excel 行。处理建议是核对基线路由组成员；工具不会自动迁移。
- 「本次路由变更统计」卡片按核心返回的功能动态生成，不代表只支持固定的两类卡片。
- 摘要卡片出现“查看详情”时，可以打开独立窗口查看本次实际计划新增、删除的报文或信号路由；已存在、未找到、冲突和跳过项不会冒充为实际变更。

问题表支持按级别筛选、全文搜索、表头排序和复制所选行（「复制所选」在没有选中行时置灰）。报文 ID 与报文名称并入规则代码列的副行：直接报文路由表本身携带 CAN ID，因此可同时显示 ID 和名称；标准信号路由表不携带 CAN ID，相关问题只显示可证明的源/目标报文名称，ID 显示为“—”，不会从项目特定映射中猜测。「位置」列只显示文件名，完整路径、工作表、行号、字段与关联报文可在双击详情弹窗中查看。底部状态条提供操作 ID、Prepared Session ID、版本和日志目录入口。

例如“本次仅删除指定目标信号；删除后该源信号仍路由到另外 2 个目标信号，因此保留 Mapping、Source 和源端超时”表示该源信号原本有多个目标，本次目标已删除，但另外两个目标仍在使用同一源端链，所以共享的 Mapping、Source 和超时配置不能一起删除。

## 取消和关闭

预览或生成期间可以点击“取消”。取消是协作式的：程序会等待下一个安全边界，因此大文件写临时文件期间可能不会立即结束。原子发布前取消会清理临时文件且不生成目标；如果原子发布已完成，结果仍会报告成功，避免把已发布文件误报为取消。

任务运行时关闭窗口，程序只询问一次是否取消并退出。确认后窗口会等待工作线程安全收尾，不会强制终止线程。

## 常见问题

- “输出文件已存在”：选择一个新文件名。程序不覆盖现有输出。
- “预览后输入发生变化”：配置表或基准的大小、修改时间或内容摘要发生变化，请重新预览。
- “Prepared Session 不可提交”：预览已失效、被消费或过期，请重新预览。
- “未解析到应用路由组、主通道歧义、成员重复/悬空或删除后为空”：按问题中的报文名称、CAN ID、通道、组名和 DestPdu 路径修正引用数据或 DaVinci 工程后重新预览。
- “目标端已被本地发送占用”或“源路由链歧义”：请按问题中的 CanIf、EcuC、PduR 完整路径检查基线。工具不会按名称前缀猜测归属，也不会自动清理历史重复链。
- 信号路由导入后仍显示 `ACCESS_UNCLEAR`：确认使用的是 1.1.5 或更高版本，并用原配置表和未手工覆盖的基线重新预览、生成。若使用更早的版本，请先升级到当前发布版再重试。
- 程序启动失败或内部失败：打开 `%LOCALAPPDATA%\DaVinciGW\logs\gui.log`，向维护者提供操作时间、版本和异常类型；不要发送涉密输入文件。
- 想看某个问题的完整定位：双击问题表对应行，会打开详情窗口，显示文件、工作表、行号、字段、关联报文与处理建议。

## 当前边界

桌面版只编排已有 GatewayFacade，不新增路由规则。当前不支持直接报文 LIN 路由、多 ARXML 合并、DaVinci 自动导入/Validate、云端服务、遥测或自动更新。

桌面版本身不监听端口。需要把客户端请求转发到独立核心时，使用单独的 Bridge 服务（见 [桌面端 Bridge 服务](桌面端Bridge服务.md)）；它默认只监听回环地址，并校验访问令牌。
