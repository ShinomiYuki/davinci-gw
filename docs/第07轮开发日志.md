# 第07轮开发日志：PduR 路由组成员关系增量维护

## 本轮目标

在既有直接报文 RoutingPath、SrcPdu、DestPdu 和 CanIf/EcuC 增量链路上，增加 DestPdu 与既有 `PduRRoutingPathGroup` 的成员关系维护。范围只包含引用增删、查询和安全校验；不创建、删除或重命名路由组，不分配 GroupId，也不修改初始化状态和无关成员。

## 最终设计

新增独立 `RoutingGroupMembershipService`。`PduREditor` 仍只负责 RoutingPath、SrcPdu 和 DestPdu，没有加入组查询、引用修改或 Excel 字符串解析。Service 接收规范化成员请求、`ArxmlDocument` 和 `ArxmlIndex`，集中完成组名唯一定位、成员查询、重复/悬空检查、幂等判断、空组批量投影以及引用节点应用。

领域 Mutation 新增 `PDUR_ROUTING_GROUP_MEMBERSHIP`，动作新增 `ADD_REFERENCE` 与 `REMOVE_REFERENCE`。操作身份由组完整路径、成员 `DEFINITION-REF` 和 DestPdu 完整 `VALUE-REF` 共同组成，不把引用伪装成 RoutingGroup 容器创建或删除，也不会因同一组维护多个成员而发生路径去重冲突。

适配层保持最小：当前只有 `MicrosarRoutingGroupAdapter`，依据真实节点类型、`DEFINITION-REF` 和 `DEST` 属性识别当前基线结构。接口只暴露成员检查与引用插入两项能力，为未来有真实样例和测试证据的其他 Vector 方向预留扩展点，没有建立版本字符串分支或推测性框架。

## DTO 与输入契约

`DirectRouteChange` 追加 `routing_group_names: tuple[str, ...]`，保持既有位置参数兼容。直接报文表新增必填列 `PduR路由组`，ADD/DELETE 均要求明确填写。Excel 边界只接受英文分号，完成裁剪、空项删除和稳定去重；业务规划、Service 和 `PduREditor` 均不接触原始单元格字符串。

旧配置表缺少新列会作为表头错误停止。工具不按目标网段、CAN 通道或项目名称猜测组名。

## 当前支持的 ARXML 结构

当前完整支持：

```text
PduRRoutingPathGroup
  REFERENCE-VALUES
    ECUC-REFERENCE-VALUE
      DEFINITION-REF = /MICROSAR/PduR/PduRRoutingTables/PduRRoutingPathGroup/PduRDestPduRef
      VALUE-REF      = <PduRDestPdu 完整路径>
```

真实 81 MB 基线中的 `PduRRoutingPathGroup_DCAN` 已通过代表性 Facade 预览和生成验证。结构不匹配时返回明确阻断错误；没有真实证据的其他引用方向列为已知限制。

## ADD/DELETE 顺序与安全策略

ADD 的处理器顺序为 EcuC、CanIf、RoutingPath、SrcPdu、DestPdu、RoutingGroup 引用，保证成员引用写入时目标已存在。既有成员返回幂等成功，不产生重复引用；路由腿已存在但成员缺失时只补成员关系。

DELETE 对全部目标腿先完成精确定位和批量成员规划。声明的成员引用先进入 `REMOVE_REFERENCE` 投影，外部引用检查会扣除这些精确引用节点，而不是绕过引用安全检查。若仍有未声明组引用则阻止删除并报告剩余组名。成员引用应用完成后才删除 DestPdu，最后沿用既有共享对象规则判断 SrcPdu、RoutingPath、CanIf 和 EcuC。

空组按同一事务内全部成员删除操作统一计算；计划后成员数为零时在修改前阻断。重复成员、悬空 VALUE-REF、组不存在、同名组不唯一、路由仍存在但声明成员缺失和不支持结构同样阻断。与本次请求无关的成员和组参数保持原字节语义。

## 测试结果

开发阶段先执行第07轮输入与成员关系专项测试，再执行直接报文、DELETE、信号、公共 Facade、MCP 和 GUI 受影响单元回归；没有在开发前重复跑完整套件。专项覆盖单组/多组 ADD、重复 ADD、单组/多组 DELETE、重复 DELETE、缺失/歧义组、未声明其他组、空组、重复/悬空成员、外部引用投影、一对多目标腿、当前 MICROSAR 结构、不支持结构及 ADD/DELETE 二次运行无差异。

代表性真实集成使用 81,085,689 字节基线和临时迁移的新契约配置表完成 Facade preview→commit，原始真实 Excel/ARXML 保持只读。交付前执行 `compileall` 与 `pip check` 均通过，并执行一次 190 项完整回归。完整回归中仅实际 GUI 压力用例的心跳间隔断言失败：阈值要求 `<1.0 s`，本次为 `1.234 s`；该用例的取消、预览、生成、81 MB 输出、单次基线读取和窗口交互断言均已通过。按既定结论将其记为环境时序抖动，不修改产品代码，也不重复执行全量回归。

## 代码审查与修复

开发中已修复四项由测试和审查暴露的问题：小型 ARXML 夹具原先省略真实引用节点的 `DEST` 属性，已统一为当前 MICROSAR 形态；DELETE→ADD 同键替换的输出验证最初把中间成员删除误判为最终必须为零，现与容器替换一致，按最终投影由后续 ADD 验证唯一成员；同名但定义不同的容器原先会被笼统报告为组不存在，现明确报告不支持的结构；成员关系错误现统一携带 DestPdu 完整路径，空组错误同时列出本次将删除的目标路径。

最终代码审查确认：`PduREditor` 未引入路由组职责，字符串拆分只存在于 Excel 输入边界，生产代码没有项目专用组名；引用级 Mutation 身份可区分同组多成员；DELETE 的引用投影、操作顺序和 ADD/DELETE 同键替换均按最终状态验证；组参数和无关成员不参与改写。`git diff --check` 无空白错误，未发现需要继续修改的功能性问题。

## 已知限制

- 只支持已经存在的 RoutingGroup；不创建/删除组，不修改组名、GroupId 或初始化状态。
- 当前只支持本轮真实 MICROSAR 直接持有 DestPdu 引用的模型。
- 路由组只适用于直接报文路由；信号路由不使用该列。
- 上游必须提供准确组名；工具不会维护项目级网段到组名映射。
