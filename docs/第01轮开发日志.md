# 第01轮开发日志：输入契约与 ARXML 基础引擎

## 本轮目标

合并完成原计划第1轮“冻结输入契约与基础工程”和第2轮“ARXML 基础引擎”：让独立 CLI 能读取并校验上游 Skill 输出的标准配置表、安全检查旧版完整 ARXML、预览变更统计，并证明大型 ARXML 可以在不修改基线的前提下无修改原子往返写出。

本轮明确不实施实际路由节点新增、删除或超时写入。

## 实际完成内容

- 建立 Python 3.12 `src` 布局的可安装包、运行/开发依赖范围、控制台入口和 pytest slow 标记。
- 定义 ADD/DELETE、来源位置、不可变路由键、变更模型、校验问题、预览和 ARXML 检查结果。
- 按第一行表头读取“引用数据”“直接报文路由”“信号路由”，支持列顺序调整、模板空白行、版本识别、类型规范化、必填/范围、重复/冲突和一对多规则。
- 使用 lxml 安全解析 ARXML，动态识别命名空间和 `schemaLocation`，按节点类型、SHORT-NAME、DEFINITION-REF 联合发现 CanIf、Com、EcuC、PduR。
- 建立可重建的 SHORT-NAME（允许多结果）、DEFINITION-REF、完整 AUTOSAR 路径和 VALUE-REF 反向引用索引。
- 实现同目录非固定临时文件、完整序列化、`fsync`、重新解析验证和 `os.replace` 的原子写出；默认拒绝覆盖及输入输出同路径。
- 提供 `validate` 和 `preview` 中文 CLI，稳定区分成功（0）、契约错误（2）和系统/损坏文件错误（3），普通模式不显示堆栈。
- 增加动态 Excel、小型脱敏 ARXML、CLI 和真实输入慢速集成测试。
- 更新用户 README、输入契约文档和 Git 忽略规则。

## 主要设计决策

1. 领域层只使用 dataclass、Enum、Decimal、Path 等通用类型，不依赖 openpyxl、lxml 或 argparse。lxml 节点引用在模块信息中以不参与比较的 `object` 保存，由 ARXML 层负责使用。
2. 应用层负责编排和异常到 `ValidationIssue` 的转换；输入、ARXML、领域层不打印、不退出进程。
3. Excel 数据量由字段内容判断，不信任模板的 `max_row`，也不因中间空行提前停止。显式空字符串和从未填写单元格在引用数据中保持可区分。
4. 模块发现不依赖排列顺序或固定深度，只接受目标节点类型以及匹配的 SHORT-NAME/DEFINITION-REF 组合；额外模块原样保留。
5. 索引不假定 SHORT-NAME 全局唯一；完整路径由祖先中具有直接 SHORT-NAME 的可识别对象构造。
6. 解析器禁用实体解析和网络访问，保留空白、注释、未知属性和未知节点；写出不使用 `pretty_print`，避免重排大型文件。
7. 同一命令对基线只完整解析一次；只有无修改写出后的安全复核会按要求重新解析输出。
8. 外部 VALUE-REF 允许保持未解析，只有根/Schema、四模块和基础结构异常阻止执行。
