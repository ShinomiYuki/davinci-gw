# 标准配置表输入契约

本文档冻结 DaVinci 网关路由工具当前读取的标准配置表契约。工具只解释已标准化的数据，不读取原始 Communication Routing Table、不分析 History，也不从自然语言说明推导新业务要求。

## 文件名与目标版本

配置表文件名必须匹配大小写不敏感规则 `*_vX.x.xlsx`，例如 `网关路由配置表_v4.84.xlsx`。版本数字的各段会去除无意义的前导零，`V04.084` 规范化为 `4.84`。

“版本”工作表中的 `V01`、`V02` 是模板版本，不是目标需求版本，工具不会读取它们作为目标版本。文件名不符合规则时返回错误：“无法从配置表文件名识别目标版本，请使用 *_vX.x.xlsx 格式。”，不会要求用户交互选择版本。

## 执行输入页

以下工作表参与执行：

- 引用数据
- 直接报文路由
- 信号路由
- 诊断报文路由（1.1.0 新增，可选）
- 诊断报文路由参数（有诊断执行行时，仅读取通用功能寻址 CAN ID）

封面、版本、命名规则、直接报文路由需求描述和 Sheet1 等其他工作表仅供人工查看或交叉引用，不会把其中的说明转换为执行要求。旧版诊断示例页若同时缺少“诊断入口类型”和“操作类型”，警告并跳过，不推断新增动作。

每张执行输入页的第一行是表头。工具按完整表头名称建立字段映射，因此允许调整列顺序；不允许删除或改名必需表头。字符串会去除首尾空格，但报文名、信号名和通道名的大小写不会改变。

## 诊断报文路由（可选）

诊断执行页使用 Skill 标准的 32 列表头，包含请求/应答端名称、CANID_REQ、CANID_RES、接收/发送报文类型、Length、CAN 通道、各端八个传输参数，以及诊断入口类型、操作类型。`OBD_CAN` 读取两端，`OBD_ETH` 仅读取 CAN 应答端。物理寻址 ADD 的两端均需八个传输参数；功能寻址以 CANID_RES 的 `/` 或空值表示，仅需请求端 N_Ar/N_Br/N_Cr/BlockSize/STmin 和目标端 N_As/N_Bs/N_Cs。DELETE 不要求传输参数。

N 参数、STmin 为非负毫秒数，写入时转换为秒；BlockSize 为 0–255 整数。CAN ID 字符串按十六进制解释，可带 `0x` 前缀。通道类型/长度以及引用、队列与寻址规则见 [1.1.0 发布说明](发布说明_v1.1.0.md)。

## 引用数据

| 字段              | 类型       | 必填 | 规则                                                        |
| ------------------- | ------------ | -----: | ------------------------------------------------------------- |
| CAN通道名称       | 字符串     |   是 | 去除首尾空格后不能为空，整张表唯一                          |
| CanIfTxBuffer名称 | 字符串或空 |   否 | ADD 时用作目标 CanIf Tx 引用；DELETE 时用于核对目标通道归属 |
| CanIfHrh名称      | 字符串或空 |   否 | ADD 时用作源 CanIf Rx 引用；DELETE 时用于核对源通道归属     |

TxBuffer 和 Hrh 会保留“显式空字符串”与“从未填写（None）”的区别。重复 CAN 通道定义为错误。

## 直接报文路由


| 字段                        | 规范化类型 |  ADD | DELETE | 其他规则                                                                 |
| ----------------------------- | ------------ | -----: | -------: | -------------------------------------------------------------------------- |
| 源网段报文名称              | 字符串     | 必填 |   必填 | 路由键                                                                   |
| 源网段报文CANID             | 整数       | 必填 |   必填 | 支持 Excel 整数、十进制字符串、`0x` 十六进制字符串；范围 `0..0x1FFFFFFF` |
| 源网段报文Length            | 整数或空   | 必填 |   可空 | 非空时范围`0..64`                                                        |
| 源网段报文类型              | 字符串或空 | 必填 |   可空 | ADD 时映射 CanIf Rx CAN ID 类型；仅支持已定义的 CAN 类型                 |
| 源网段CAN通道               | 字符串     | 必填 |   必填 | 路由键                                                                   |
| 源网段RxIndicationUL        | 字符串或空 | 必填 |   可空 | ADD 时写入 CanIf Rx 上层接收模块                                         |
| 源网段报文Checksum使能      | 字符串或空 | 可空 |   可空 | 本轮保存                                                                 |
| 源网段报文Dlc Check使能     | 字符串或空 | 必填 |   可空 | ADD 时`Enable` 映射为 `true`，其他规范值映射为 `false`                   |
| 目标网段报文名称            | 字符串     | 必填 |   必填 | 路由键                                                                   |
| 目标网段报文CANID           | 整数       | 必填 |   必填 | 与源 CAN ID 相同的解析和范围规则                                         |
| 目标网段报文Length          | 整数或空   | 必填 |   可空 | 非空时范围`0..64`                                                        |
| 目标网段报文类型            | 字符串或空 | 必填 |   可空 | ADD 时映射 CanIf Tx CAN ID 类型；仅支持已定义的 CAN 类型                 |
| 目标网段CAN通道             | 字符串     | 必填 |   必填 | 路由键                                                                   |
| 目标网段报文Checksum使能    | 字符串或空 | 可空 |   可空 | 本轮保存                                                                 |
| 目标网段报文PnFilter使能    | 字符串或空 | 可空 |   可空 | 本轮保存                                                                 |
| 目标网段报文Truncation使能  | 字符串或空 | 必填 |   可空 | ADD 时`Enable` 映射为 `true`                                             |
| 路由Length Strategy功能选择 | 字符串或空 | 必填 |   可空 | ADD 时写入 PduR Destination；不支持的值逐路由警告跳过                    |
| 操作类型                    | 枚举       | 必填 |   必填 | 去除空格并转为大写，只允许`ADD`、`DELETE`                                |

DELETE 行只用身份字段定位路由；其他参数允许为空。若 DELETE 行填写了 CAN ID、Length 等参数，它们仍须满足格式和范围约束。

直接报文路由唯一键为：

```text
(源报文名称, 源CAN ID, 源CAN通道, 目标报文名称, 目标CAN ID, 目标CAN通道)
```

CAN ID 在领域层保存为整数，显示时统一格式化为大写十六进制，例如 `0x47A`。

“直接报文路由”保持标准 A:R 共 18 列，不包含也不需要 `PduR路由组`。GUI、MCP、CLI 和公共 Facade 均不提供额外组名输入。

工具从基准 ARXML 的实际成员引用反查 EcuC PDU、CanIfTxPdu 和 TxBuffer，再与“引用数据”的目标通道建立动态索引。组内唯一最高计数通道是主通道；并列、同一通道对应多个主组或目标通道没有应用组时阻断。只含 CanTp/DoIP 等非 CanIf 成员的诊断组不参与普通直接报文选择。工具不创建、删除或重命名 RoutingGroup。

DELETE 必须同时核对 PduR RoutingPath/SrcPdu/DestPdu、EcuC PDU、CanIf Rx/Tx、CAN ID、HRH/TxBuffer、方向和引用关系，不只凭 SHORT-NAME 删除。目标腿不存在时记为“已不存在”并幂等跳过；候选不唯一、语义不一致或目标子树仍有外部引用时阻止全部输出。

删除指定 Destination 后，仍有其他目标、共享引用或人工子容器的 RoutingPath/CanIf/EcuC 对象会保留，并产生结构化保留原因。HRH、TxBuffer、CanIf 控制器/硬件对象和 PduR BSW 模块配置不属于删除范围。

### PduR 路由组成员关系

当前明确支持以下 MICROSAR 结构：

```text
/MICROSAR/PduR/PduRRoutingTables/PduRRoutingPathGroup
  REFERENCE-VALUES/ECUC-REFERENCE-VALUE
    DEFINITION-REF = /MICROSAR/PduR/PduRRoutingTables/PduRRoutingPathGroup/PduRDestPduRef
    VALUE-REF      = <PduRDestPdu 完整 AUTOSAR 路径>
```

识别依据是真实 `DEFINITION-REF`、直接节点结构和 `DEST` 属性，不使用 AUTOSAR 版本字符串。其他引用方向或结构会以“不支持的路由组模型”阻止输出，不会臆造兼容。

ADD 先按目标通道解析唯一主应用组，再创建或确认 RoutingPath、SrcPdu、DestPdu，最后加入 DestPdu 引用；引用已存在时幂等成功且不重复。DELETE 通过 Rx/Tx、CAN ID、HRH/TxBuffer、EcuC 和 PduR 引用链语义定位旧/新命名对象，反查实际组并与目标通道主组核对，再删除精确引用并更新外部引用投影。

以下情况会在写出前阻止整个事务：主通道并列、通道到主组不唯一、目标通道无应用组、结构不支持、同组重复成员、成员 VALUE-REF 悬空、实际组与主组不一致、DestPdu 属于多个组或批量删除后组将为空。非主通道少数成员只产生基线一致性警告，不会污染动态映射。一个 RoutingPath 的多个 DestPdu 按目标腿分别维护；无关成员、组名、`PduRRoutingPathGroupId` 和 `PduRIsEnabledAtInit` 保持原样。

## 信号路由


| 字段         | 规范化类型       |  ADD | DELETE | 其他规则                                                                |
| -------------- | ------------------ | -----: | -------: | ------------------------------------------------------------------------- |
| 源网段       | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 源报文名     | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 源信号名     | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 字节序       | 字符串或空       | 可空 |   可空 | 本轮只保存，不映射 ARXML                                                |
| 超时值       | 非负十进制数或空 | 可空 |   可空 | 非空时必须有限且不小于 0；存在超时时间时作为源 ComSignal 替代值直接写入 |
| 超时时间     | 非负十进制数或空 | 可空 |   可空 | 非空时必须有限且不小于 0；ADD 时直接使用上游标准值，不反推 Cycle Time   |
| 源信号组合名 | 字符串或空       | 可空 |   可空 | 本轮保存                                                                |
| 目标网段     | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 目标报文名   | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 目标信号名   | 字符串           | 必填 |   必填 | 路由键                                                                  |
| 操作类型     | 枚举             | 必填 |   必填 | 只允许`ADD`、`DELETE`                                                   |

信号路由唯一键为：

```text
(源网段, 源报文名, 源信号名, 目标网段, 目标报文名, 目标信号名)
```

DELETE 通过源/目标 ComIPdu 的方向与 `ComIPduSignalRef` 验证信号归属，再按源 ComSignal 引用定位 Mapping、按目标 ComSignal 引用定位 Destination。Mapping 或 Destination 已不存在时幂等跳过；Source/Destination 结构不唯一或目标子树仍被外部引用时阻止输出。

LIN 信号定位不内置逻辑节点到物理通道的项目映射。常规网段标记定位为零时，只有报文名、信号名、方向和 `ComIPduSignalRef` 关系在全部 CAN/LIN 端点中唯一，且实际 ComIPdu 明确为 LIN，才接受该结构候选。多 LIN 或 CAN/LIN 同名候选均为阻断错误。

## 源端超时的 DELETE 证据

只有以下条件同时满足，才删除本工具涉及的 `ComRxDataTimeoutAction`、`ComTimeout` 和可选的 `ComRxDataTimeoutSubstitutionValue`：

1. 整批 DELETE 投影中，该源信号已无任何 Destination 或其他 Mapping。
2. 本次 ADD 不再使用该源 ComSignal。
3. DELETE 行的非空超时值在同源全部行中一致，且与 ARXML 当前唯一参数完全相等。
4. 删除不会影响其他现存信号路由。

DELETE 超时字段为空、当前值不一致、参数重复、仍有共享 Mapping/目标或 ADD 继续使用时，超时保守保留，并在 preview/generate 报告中说明原因。

## 空行、重复、一对多和冲突

- 工具遍历工作表的全部候选行，不使用 `max_row` 作为有效数据量，也不会在第一个空行处停止。
- 所有输入字段都为空或只含空格的行会被忽略，因此模板格式扩展到大量空白行不会产生记录。
- 身份字段或操作类型存在的部分填写行会参与校验，并报告缺失字段。
- 同一路由键和同一操作出现两次是重复错误，问题定位到后出现的工作表行，并提示首次出现行号。
- 同一路由键最多允许一条 DELETE 和一条 ADD，两者组成合法替换对，固定先删后增。ADD 仍必须提供完整新参数；DELETE 目标已不存在时仍允许执行 ADD，但 DELETE 无法安全完成时不会用 ADD 强制覆盖。
- 同一源端路由到不同目标端时完整路由键不同，是合法的一对多；每个目标保留为独立的一对一路由腿。

## 错误、警告与退出边界

以下问题是阻止执行的契约或安全错误：缺失文件/工作表/表头、无法识别目标版本、必填字段为空、类型或范围无效、通道重复、同键同操作重复、必要 ARXML 模块缺失/重复，以及 DELETE 候选不唯一、语义冲突、路由组结构冲突、空组风险或会引入悬空引用。CLI 返回退出码 `2`。

文件损坏、Excel 无法读取、XML 语法解析失败和底层 I/O 失败属于系统类错误，CLI 返回退出码 `3`。普通模式不显示堆栈；`--debug` 会输出被结构化问题保留的原始异常。

非阻断 WARNING 包括 DELETE 目标已不存在，以及单条 ADD 缺少 DBC/HRH/TxBuffer 而被跳过。共享对象或超时的保守保留是结构化决策，不是错误；preview 和 generate 会列出保留路径与原因。无法在当前 ARXML 中解析的历史外部 `VALUE-REF` 本身不作为错误，但本次计划删除的对象或子对象如果仍有输出内部引用，必须阻止。
