# 标准配置表输入契约

本文档冻结 DaVinci 网关路由工具第01轮读取的标准配置表契约。工具只解释已标准化的数据，不读取原始 Communication Routing Table、不分析 History，也不从自然语言说明推导新业务要求。

## 文件名与目标版本

配置表文件名必须匹配大小写不敏感规则 `*_vX.x.xlsx`，例如 `网关路由配置表_v4.84.xlsx`。版本数字的各段会去除无意义的前导零，`V04.084` 规范化为 `4.84`。

“版本”工作表中的 `V01`、`V02` 是模板版本，不是目标需求版本，工具不会读取它们作为目标版本。文件名不符合规则时返回错误：“无法从配置表文件名识别目标版本，请使用 *_vX.x.xlsx 格式。”，不会要求用户交互选择版本。

## 执行输入页

只有以下三张工作表参与执行：

- 引用数据
- 直接报文路由
- 信号路由

封面、版本、命名规则、诊断报文路由、诊断报文路由参数、直接报文路由需求描述和 Sheet1 等其他工作表仅供人工查看或交叉引用，本轮不会把其中的说明转换为执行要求。

每张执行输入页的第一行是表头。工具按完整表头名称建立字段映射，因此允许调整列顺序；不允许删除或改名必需表头。字符串会去除首尾空格，但报文名、信号名和通道名的大小写不会改变。

## 引用数据

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| CAN通道名称 | 字符串 | 是 | 去除首尾空格后不能为空，整张表唯一 |
| CanIfTxBuffer名称 | 字符串或空 | 否 | 本轮只解析、保存和预览，后续轮次使用 |
| CanIfHrh名称 | 字符串或空 | 否 | 本轮只解析、保存和预览，后续轮次使用 |

TxBuffer 和 Hrh 会保留“显式空字符串”与“从未填写（None）”的区别。重复 CAN 通道定义为错误。

## 直接报文路由

| 字段 | 规范化类型 | ADD | DELETE | 其他规则 |
|---|---|---:|---:|---|
| 源网段报文名称 | 字符串 | 必填 | 必填 | 路由键 |
| 源网段报文CANID | 整数 | 必填 | 必填 | 支持 Excel 整数、十进制字符串、`0x` 十六进制字符串；范围 `0..0x1FFFFFFF` |
| 源网段报文Length | 整数或空 | 必填 | 可空 | 非空时范围 `0..64` |
| 源网段报文类型 | 字符串或空 | 必填 | 可空 | 本轮保存，不映射 ARXML |
| 源网段CAN通道 | 字符串 | 必填 | 必填 | 路由键 |
| 源网段RxIndicationUL | 字符串或空 | 必填 | 可空 | 本轮保存 |
| 源网段报文Checksum使能 | 字符串或空 | 可空 | 可空 | 本轮保存 |
| 源网段报文Dlc Check使能 | 字符串或空 | 必填 | 可空 | 本轮保存 |
| 目标网段报文名称 | 字符串 | 必填 | 必填 | 路由键 |
| 目标网段报文CANID | 整数 | 必填 | 必填 | 与源 CAN ID 相同的解析和范围规则 |
| 目标网段报文Length | 整数或空 | 必填 | 可空 | 非空时范围 `0..64` |
| 目标网段报文类型 | 字符串或空 | 必填 | 可空 | 本轮保存，不映射 ARXML |
| 目标网段CAN通道 | 字符串 | 必填 | 必填 | 路由键 |
| 目标网段报文Checksum使能 | 字符串或空 | 可空 | 可空 | 本轮保存 |
| 目标网段报文PnFilter使能 | 字符串或空 | 可空 | 可空 | 本轮保存 |
| 目标网段报文Truncation使能 | 字符串或空 | 必填 | 可空 | 本轮保存 |
| 路由Length Strategy功能选择 | 字符串或空 | 必填 | 可空 | 本轮保存 |
| 操作类型 | 枚举 | 必填 | 必填 | 去除空格并转为大写，只允许 `ADD`、`DELETE` |

DELETE 行只用身份字段定位路由；其他参数允许为空。若 DELETE 行填写了 CAN ID、Length 等参数，它们仍须满足格式和范围约束。

直接报文路由唯一键为：

```text
(源报文名称, 源CAN ID, 源CAN通道, 目标报文名称, 目标CAN ID, 目标CAN通道)
```

CAN ID 在领域层保存为整数，显示时统一格式化为大写十六进制，例如 `0x47A`。

| 字段 | 规范化类型 | ADD | DELETE | 其他规则 |
|---|---|---:|---:|---|
| 源网段 | 字符串 | 必填 | 必填 | 路由键 |
| 源报文名 | 字符串 | 必填 | 必填 | 路由键 |
| 源信号名 | 字符串 | 必填 | 必填 | 路由键 |
| 字节序 | 字符串或空 | 可空 | 可空 | 本轮只保存，不映射 ARXML |
| 超时值 | 非负十进制数或空 | 可空 | 可空 | 非空时必须有限且不小于 0 |
| 超时时间 | 非负十进制数或空 | 可空 | 可空 | 非空时必须有限且不小于 0 |
| 源信号组合名 | 字符串或空 | 可空 | 可空 | 本轮保存 |
| 目标网段 | 字符串 | 必填 | 必填 | 路由键 |
| 目标报文名 | 字符串 | 必填 | 必填 | 路由键 |
| 目标信号名 | 字符串 | 必填 | 必填 | 路由键 |
| 操作类型 | 枚举 | 必填 | 必填 | 只允许 `ADD`、`DELETE` |


## 空行、重复、一对多和冲突

- 工具遍历工作表的全部候选行，不使用 `max_row` 作为有效数据量，也不会在第一个空行处停止。
- 所有输入字段都为空或只含空格的行会被忽略，因此模板格式扩展到大量空白行不会产生记录。
- 身份字段或操作类型存在的部分填写行会参与校验，并报告缺失字段。
- 同一路由键和同一操作出现两次是重复错误，问题定位到后出现的工作表行，并提示首次出现行号。
- 同一路由键同时出现 ADD 和 DELETE 是冲突错误。
- 同一源端路由到不同目标端时完整路由键不同，是合法的一对多；每个目标保留为独立的一对一路由腿。

## 错误、警告与退出边界

以下问题是阻止执行的契约错误：缺失文件或工作表、缺失表头、无法识别目标版本、必填字段为空、类型或范围无效、通道重复、路由重复/冲突，以及必要 ARXML 模块缺失或重复。CLI 返回退出码 `2`。

文件损坏、Excel 无法读取、XML 语法解析失败和底层 I/O 失败属于系统类错误，CLI 返回退出码 `3`。普通模式不显示堆栈；`--debug` 会输出被结构化问题保留的原始异常。

第01轮没有定义会自动放宽契约的警告。未来新增非阻止性提示时使用 WARNING，不得把本节列出的错误降级为警告。无法在当前 ARXML 中解析的外部 `VALUE-REF` 不作为错误，因为它可能合法地指向其他文件中的对象。
