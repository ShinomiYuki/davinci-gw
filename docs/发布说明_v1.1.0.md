# DaVinci 网关路由工具 1.1.0

核心、GUI、MCP 统一升级为 1.1.0。标准配置表新增可选“诊断报文路由”页，旧配置表继续可用。

旧版示例诊断页若同时缺少“诊断入口类型”和“操作类型”，显示警告并保持不执行，不推断 ADD。新版执行页字段不完整时仍阻止输出。

## CAN 诊断配置

- `OBD_CAN` 物理寻址配置请求和响应两个方向，功能寻址只配置请求。
- `OBD_ETH` 仅新增或删除 CAN 侧 CanIf、两层 EcuC、CanTp，不选择、配置或校验 DoIP，不新增跨协议 PduR。
- 按 CAN ID、HRH/TxBuffer、完整引用链定位已有对象，不用 CanTp Channel 名称猜测物理通道。
- BD/DM/DG 新建端点使用经典 CAN：Rx `STANDARD_NO_FD_CAN`，Tx `STANDARD_CAN`，DLC=8；其他通道为 `STANDARD_FD_CAN`，DLC=64。新建 CanTp Dl 对应 8/64，TaType 对应物理或功能寻址。
- CanIf Rx 使用 `CanTp_RxIndication`、`CAN_TP`、DlcCheck=false；Tx 使用 `CanTp_TxConfirmation`、`CAN_TP`、Truncation=true。
- N_As、N_Bs、N_Cs、N_Ar、N_Br、N_Cr、STmin 输入统一为 ms，写入 ARXML 时除以 1000；BlockSize 为 0–255 整数。已有值与输入冲突时拒绝覆盖。
- 功能寻址以 CANID_RES 的 `/` 或空值表示，只有请求 Rx 和目标 Tx；不创建响应或 FC。
- 每个新增 PduR 目标腿独占 `PduRQueue/PduRSharedBufferQueue`。普通 Depth=3，7DF 或功能寻址 Depth=5，TpThreshold=0；缓冲池引用复用基线唯一组合。
- 独立 Queue 在最后一个使用它的目标腿删除后清理，共享端点、队列、缓冲池和其他目的腿保留。硬件引用缺失时警告并跳过整行。
- 新建对象的非输入参数、上层 N-SDU 长度由同类基线唯一确定；证据不唯一时明确报错，不选首个候选。

## 信号和命名

源信号超时替代值独立写入 Rx `ComRxDataTimeoutSubstitutionValue`，可与超时时间分别配置。十六进制输入支持 `0x` 前缀。Tx 替代值保持不变。

新建普通端点名为 `GWT_CanIf_{报文}_{CANID}_{完整通道}_{Rx|Tx}` 与 `GWT_EcuC_...`。诊断下层使用 `GWT_Diag_CanIf_...`、`GWT_Diag_EcuC_...`，上层使用 `GWT_Diag_Tp_EcuC_...`。已有对象不改名。

新建 PduR 目标腿命名为 `Diag_TP_{目标CANID}_{目标网段}`，例如 `Diag_TP_7E0_PTCAN`。CanTp Channel 是包含 N-SDU 的真实分组：物理寻址命名为 `GWT_CanTpChannelGW_{网段}{请求ID}_{响应ID}`，功能寻址为 `GWT_CanTpChannelGW_{网段}{请求ID}`。通道归属依照引用链，避免沿用基线中与实际通道不符的名称。

## 真实场景验证口径

需求表 OBD CAN 页第 20、36 行，R 列、ADD、请求通道 DG：7E0/7E8 为 DG 与 PT 间双向物理路由，7DF 为 DG 到 IC 的单向功能寻址。原始基线已存在这两条路由，ADD 幂等。完整链路验收在独立副本中移除对应 CanIf、两层 EcuC、CanTp 与依赖的 PduR 引用，再通过正常生成入口重建。原始需求表与 ARXML 不修改。

实际新增 3 个 CanIf Rx、3 个 CanIf Tx、12 个 EcuC PDU、4 个 CanTp Channel、3 个 Rx N-SDU、3 个 Tx N-SDU、3 个 Rx N-PDU、3 个 Tx N-PDU、2 个 Rx FC、2 个 Tx FC、3 条 PduR 路径、3 个源、3 个目标、3 个 Queue 和 3 个 SharedBufferQueue。输出复核和再次 ADD 幂等验证通过。测试副本清除了共享端点的其他 PduR 使用方，仅用于选定需求的重新生成验收。

发布标签为 `v1.1.0`，GitHub Release 包含 GUI、MCP Windows x64 ZIP 及对应校验文件，不包含客户工作簿或 ARXML。

## 审查与验证

原生代码审查发现的专用 Queue 删除遗留问题已修复；复审未发现明确缺陷。针对性测试覆盖物理寻址、功能寻址、CAN 侧独立配置、一对多、共享保留、幂等以及 ADD→DELETE→ADD。

完整链路真实场景和诊断单元测试共 13 项通过。真实测试通过 `DAVINCI_GW_DIAGNOSTIC_CONFIG` 指定标准表，通过 `DAVINCI_GW_DIAGNOSTIC_TEST_DIR` 指定空输出目录；使用本地 `input/T13J_918.arxml`，缺少配置路径时跳过。

完整回归曾得到 247 项通过、3 项等待发布 EXE 验证；大型 GUI 的取消、预览、生成成功，最大心跳间隔 1.297 秒超过测试 1 秒阈值。用户确认该性能偏差不作为阻断项，代码与阈值保持不变。
