# DaVinci 网关路由工具 1.2.1

修复信号路由中真实端点因生成对象名称差异而被误判缺失的问题。源端使用 `ComIPduDirection=RECEIVE`，目标端使用 `SEND`；生成名称末尾的 Rx、Tx 不决定方向。

端点定位检查 `ComPduIdRef` 指向的 PDU 有效且唯一，并通过 `ComIPduSignalRef` 确认信号真实归属。结合 `ComIPduGroupRef` 和 `ComSystemTemplateSystemSignalRef` 中可明确识别的逻辑网段、报文和原始信号身份核对配置表，不再要求 ComIPdu、ComSignal 的生成名称遵循固定拼接格式。分组仅证明 Com 逻辑归属，不代表已证明物理 CAN 通道。

结构、网段和方向一致且候选唯一时，接受精确信号原名及已确认的“原名＋网段 CAN＋十进制编号”后缀。不会把 Req、Backup 等名称任意截断为别名。原始引用优先于生成名称，多个有效候选不会按名称相似程度选择。

ADD 和 DELETE 共用定位依据。源端真正缺失时跳过该源相关路由腿，单个目标缺失时只跳过对应腿；名称差异但身份未确认、归属未确定、引用冲突和候选不唯一分别提示。DELETE 保留悬空引用保护，无法归属的悬空网关引用也阻止输出。

标准信号表保持 11 列，不增加 CAN ID 或信号位置。既有 LIN 处理、多源目标冲突和纯 Event 策略保持原有行为。客户工作簿和 ARXML 只用于本地只读复验，不进入源码或发行包。工具验证不能替代 DaVinci 的实际 Validate/Generate。

版本标签为 `v1.2.1`。GitHub Release 提供 GUI、MCP Windows x64 ZIP 和对应校验文件；核心、GUI、MCP 与 Windows 版本资源统一为 1.2.1。新增目标容器沿用 `ComGwDestination_to_<目标网段>`。

验证覆盖 86 项端点定位与 ADD/DELETE 针对性测试、既有回归、大型真实输入 GUI 响应检查，以及两份本地基准的只读样例复验。原生代码审查发现的 LIN 冲突回退和 DELETE 裸报文名引用保护问题已修复，最终复审未发现相关缺陷。
