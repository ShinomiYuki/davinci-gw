# DaVinci 网关路由工具 1.1.2

修正普通 CAN 诊断需求位于 `DIAG Message routing(OBD ETH)` 页时的配置方式。页名是需求来源；当请求网段明确为 DG，M/P 列分别是请求和响应 CAN ID，K 列是目标 CAN 网段，标准配置表应填入 DG 与目标网段两个端点，并按普通 CAN 诊断生成双向 PduR。仅在明确要求以太网诊断时才处理 DoIP。

标准配置表即使标记为 `OBD_ETH`，只要显式填入请求端 CAN ID 或通道，工具也会读取并生成双端 CAN 路由；这些 CAN 身份字段只填一部分时会按缺项报错，不再静默忽略。仅有请求侧非 CAN 参数的旧单侧输入仍可读取。

Robotaxi 第 18–20、35–44、65–71、79、99–101、108–109、137 行从原始基准 ARXML 重新生成：27 条 DG→DK/IC/BD/EP/DM/SU/DA 路由新增、0 条重复或跳过；输出包含 54 条 PduR RoutingPath、54 个目标腿和 54 个独立 Queue。每个 Queue 均含 PduRSharedBufferQueue，Depth=3、TpThreshold=0，目标腿分别引用各自的 Queue。BD/DM/DG 的 Rx 为 STANDARD_NO_FD_CAN、Tx 为 STANDARD_CAN、Length 8；其他目标网段的 Rx/Tx 均为 STANDARD_FD_CAN、Length 64。CanTp 符号名沿用 1.1.1 的基准命名规则。客户输入表与 ARXML 不包含在公开发布包中。

PduR 响应路由组现在沿引用索引定位已有 CanTp/CanIf 端点，避免在大型 ARXML 上反复扫描所有端点。相同 CAN ID 下已有的 Mirror 或测试 CanIf PDU 若未连接 CAN_TP，保持原样，不再被误判成诊断端点。新增来自 OBD ETH 页但实际为双端 CAN 路由的回归测试；Windows x64 GUI 与 MCP 发布包均使用 1.1.2 版本号。
