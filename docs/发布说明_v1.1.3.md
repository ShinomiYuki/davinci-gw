# DaVinci 网关路由工具 1.1.3

修复 CAN 诊断路由新增时 PduR Source 容器全部命名为 `Source`，导致 DaVinci 对不同 Source Pdu Handle Id 报 `AR-ECUC02108` 的问题。新建 `PduRSrcPdu` 现在使用包含 ECU、CAN ID 和源网段的唯一 `GWT_Diag_...` 短名，与基准 ARXML 中 `Gw_<报文>_0x<CAN ID>_<网段>` 的命名方式一致。既有对象的名称与 Handle ID 保持不变。

本版包含 1.1.2 的 DG→目标 CAN 普通诊断路由支持。Robotaxi `DIAG Message routing(OBD ETH)` 页第 18–20、35–44、65–71、79、99–101、108–109、137 行共 27 条需求，从原始基准 ARXML 生成 54 条双向 PduR RoutingPath 和 54 个独立 Queue。每个 Queue 均有 PduRSharedBufferQueue，Depth=3、TpThreshold=0。BD、DM、DG 网段 Rx=`STANDARD_NO_FD_CAN`、Tx=`STANDARD_CAN`、长度 8；其他网段 Rx/Tx=`STANDARD_FD_CAN`、长度 64。源表和生成 ARXML 不包含在公开发布包中。

已对修正输出核对 54 个新增 Source 短名和 Handle ID 均各自唯一，且全部 `PduRSrcPdu` 无同名但符号值不同的容器。Windows x64 GUI 与 MCP 发布包版本均为 1.1.3。
