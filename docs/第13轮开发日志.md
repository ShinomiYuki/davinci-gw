# 第13轮开发日志：MCP 1.0 故障自修复与 onedir 发布

## 本轮目标

本轮将 MCP 单独升级为 1.0.0，解决 PyInstaller `onefile` 每个会话重复解包 `_MEI*`、大量占用系统盘的问题，并增加经两次用户确认的工具 BUG 自修复闭环。GUI 和核心版本保持不变。

## 主要实现

- MCP 改为 `onedir`：多个会话共用安装目录中的 `_internal`，发布形式仍为一个 Windows x64 ZIP。
- 构建时写入版本、准确 Git commit、工作区是否干净和 UTC 构建时间；自动修复只能从可追溯的干净构建启动。
- 安装器校验发布包全部文件，并按版本并列安装；升级只切换 Codex 配置，不覆盖可能仍在运行的旧版本。
- 安装清单保留全部受管版本及文件哈希；卸载器逐个验证并删除所有受管运行时，不猜测删除清单外文件。
- 新增失败分类：DBC 缺失、输入问题、基线问题、工具 BUG、无法确定。DBC 缺失行保持跳过，其他可完成路由仍可生成。
- 只有稳定复现且具有具体代码证据的工具 BUG 才能取得修复资格。
- 第一次固定确认语之后，才从 MCP 构建 commit 创建独立 `hotfix/mcp-auto-*` 分支和 worktree。
- 修复代理通过官方 `openai-codex` SDK 完成原因复核、最小修改、针对性测试、完整 diff 审查、审查修复和最终复核。
- worktree 的 `src` 被显式加入 `PYTHONPATH`，防止 Miniconda editable 安装让测试误用主工作区源码。
- 协调器随后只执行一次最终全量回归，使用原 Excel/ARXML 重新生成并验证，再构建 onedir 候选包和执行 STDIO、多进程冒烟。
- 第二次固定确认语之前，不提交、合并、推送、打标或发布。
- 外部用户只能推送自己的 Fork 并创建 Draft PR；维护者模式会检查干净 `main`、同步远端、拒绝分叉、必要时变基并重新验证。
- 新增只读 PR CI 和手工 MCP Release 工作流；外部 PR 不使用 `pull_request_target`，也没有发布权限。

## MCP 工具

在原有校验、预览和生成工具之外，新增：

- `diagnose_generation_failure`
- `start_bug_repair`
- `get_bug_repair_status`
- `submit_bug_repair`
- `cancel_bug_repair`

开始修复和正式提交使用不同确认语。取消也要求固定确认语，并保留 worktree 和修复报告供人工排查。

## 代码审查与修复

完整审查本轮 diff、所有新增文件和受影响调用点后，实际修复了以下问题：

- 修复诊断成功响应中 `summary` 重复传参导致适配器返回内部失败。
- 锁释放后立即清空持有路径，避免取消或关闭流程二次释放时误删后来者的锁。
- 审查修复后增加最终只读复核，并把审查发现写入修复报告。
- 正式提交前增加 staged diff 空白错误检查，覆盖未跟踪的新文件。
- 最终回归和变基后回归强制使用 worktree `PYTHONPATH`。
- 维护者提交先获取远端 `main`，只允许快进或保留本地领先提交，分叉时阻断且不强推。
- GitHub Release 由 `gh release create --target` 创建标签，并同时上传 ZIP 与 SHA-256 文件。
- 正式发布工作流限制只能从 `main` 运行。
- 修复 onedir 暂存复制对 `-LiteralPath` 使用通配符导致内容无法复制的问题。
- 升级后安装清单不再丢失旧版本信息，卸载会覆盖全部受管版本。
- 恢复 README 中误删的既有文档索引。
- 真实 onedir 冒烟发现无 `USERPROFILE` 时会提前求值 `Path.home()`；改为优先惰性使用 `LOCALAPPDATA`，并补充多进程存活断言，避免只检查 `_MEI*` 而漏掉启动失败。
