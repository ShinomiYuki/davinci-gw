# DaVinci 网关路由工具 1.1.1

修复新增 CAN 诊断端点时从不同 CAN 网段混用 CanTp 样板的问题。原先同一寻址类型的样板若引用不同上层 EcuC PDU 长度（例如 8 与 64），生成器会报“长度无法唯一确定”并停止。现在先沿实际 CanIf 硬件引用和底层 PDU 引用选取目标网段的 CanTp N-SDU；若该网段没有同类样板，仅在全局候选参数仍唯一时回退，冲突仍安全报错。

新增 CanTp 子容器也按基准的命名格式写入：`CanTpRxNSdu_{ECU}_{网段}`、`CanTpTxNSdu_{ECU}_{网段}`，各 N-PDU 和 FC 子容器使用对应请求或应答 CAN ID 后缀；仅当同名已被占用时追加通道与请求/应答 ID 消歧。修复原先所有新 Channel 下都叫 `CanTpRxNSdu`、`CanTpTxNPdu` 等，导致 DaVinci 报符号名相同但 Handle ID 不同的错误。输出校验现在检查新增 CanTp 符号名及 Handle ID 的唯一性。

Robotaxi 的 `DIAG Message routing(OBD ETH)` 第 18–20、35–44 行已用标准表在完整基准 ARXML 上验证：13 条独立 CAN 侧路由全部新增，0 条重复、0 条跳过，输出复核通过。`OBD_ETH` 继续只配置 CanIf、底层及上层 EcuC、CanTp；不新增 DoIP 或跨协议 PduR。该客户工作簿与 ARXML 不包含在公开发布包中。

诊断路由单元测试 14 项通过，其中增加了不同网段上层 PDU 长度不同、以及多条新路由的 CanTp 子容器短名不冲突的回归测试。Windows x64 发布包包含 GUI 与 MCP 两个 ZIP 及其 SHA-256 校验文件。
