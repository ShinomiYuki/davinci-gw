# DaVinci 网关路由工具 1.2.2

普通直接报文路由与 CanTp 诊断路由新建 CanIf Tx 时，不再写入 `CanIfTxPduTruncation` 参数。该变更删除自动使能策略，不写入显式 false；参数缺省时的界面显示和默认值以具体 DaVinci 工程为准。

标准配置表保持列布局，P 列“目标网段报文Truncation使能”默认留空，ADD 不再要求填写。旧表中的 Enable/Disable 兼容读取，但不再控制该参数。既有端点的参数为 true、false 或缺失均不影响路由定位、复用和重复执行；正常配置流程保留既有值，不修改未参与路由的 Tx。

上游 `build-gateway-routing-config` Skill 更新为 1.3.3，同步写表、校验、空白模板与需求描述。模板仍保留原有布局和 Excel 验证扩展。

新增 `remove-routed-tx-truncation` Skill 1.0.0，入口为 `skills/remove-routed-tx-truncation/scripts/remove_routed_tx_truncation.py`。先通过 `--input <基准.arxml>` 只读预览；添加 `--output <新的.arxml>` 执行清理。脚本依据 CanIf、EcuC、PduR、CanTp 的实际引用，删除既有普通直接路由和 CanTp 诊断路由所用 Tx 的参数节点，返回对象路径及删除数量。数据发送与流控共享的底层 Tx 必须能证明各业务都参与路由；不参与路由、引用歧义或其他业务共享不明确时保留并报告。输入只读，禁止覆盖已有输出，重复执行不重建参数。

两个 Skill 随仓库源码分发，复制完整对应目录到客户端 Skill 目录即可使用；清理脚本需要 Python 3.12 和 lxml。原有 Com 信号端点定位与 `ComGwDestination_to_<目标网段>` 命名保持不变。

版本标签为 `v1.2.2`。GUI、MCP、核心及 Windows 版本资源统一为 1.2.2，GitHub Release 提供 GUI、MCP Windows x64 ZIP 和对应校验文件。公司镜像同步提交和标签，二进制以 GitHub Release 为准。

验证使用人工构造的工作簿和 ARXML，覆盖生成策略、空白与旧表、路由复用、删除、参数清理、无路由保护和共享冲突。未修改客户配置，也未执行 DaVinci 的实际 Validate/Generate。
