# 第03轮开发日志：报文与信号路由安全删除

## 本轮目标

在第02轮 ADD 能力上增加直接报文与信号路由 DELETE，并把同一配置表中的直接报文 ADD/DELETE、信号 ADD/DELETE 合并为一次全成功或全失败的事务。安全不变量是：不猜测归属、不误删共享/人工配置、不读取陈旧索引、不修改输入、失败不留半成品。

## 最终设计

`MutationOperation` 使用显式 `MutationAction`：`CREATE`、`REMOVE`、`UPSERT_PARAMETERS`、`REMOVE_PARAMETERS`和用于输出复核的 `RETAIN`。`RetentionDecision` 独立记录保留路径、原因、类别与 Excel 来源行，不在领域对象中保存 lxml 节点。

`TransactionCoordinator` 对新加载的可丢弃 ARXML 工作树执行：

```text
输入预检
→ 在初始共享索引上完成整批 DELETE 规划
→ 应用 DELETE
→ 仅在删除阶段实际改变树时重建一次投影索引
→ 在投影上规划并应用 ADD
→ 临时文件序列化、重新解析和输出复核
→ 原子替换目标
```

DELETE/ADD 规划或应用失败时整个内存工作树丢弃。ADD 内部仍使用插入回滚上下文，便于单模块维持局部不变量。文件写出使用同目录临时文件和 `os.replace`，任何序列化/解析/验证失败都在 `finally` 中清理临时文件。

## 直接报文 DELETE

定位身份同时包含源/目标报文名、CAN ID 和 CAN 通道。确定性命名只用于生成候选路径，删除前还必须通过以下语义复核：

- RoutingPath 唯一，SrcPdu 总数和源 PDU 引用均唯一。
- Destination 的 SHORT-NAME 候选与目标 EcuC PDU 引用候选是同一对象。
- Src/Dest 方向分别为 RECEIVE/TRANSMIT。
- CanIf Rx/Tx 的 CAN ID、EcuC PDU 引用和 HRH/TxBuffer 引用与配置表身份一致。

计划先删指定 PduR Destination，再在“所有计划删除已发生”的投影上计算引用。目标 CanIf Tx/EcuC 和源 CanIf Rx/EcuC 只在引用归零、对象归属明确、没有人工子容器且整个子树无外部引用时删除。RoutingPath 仍有其他 Destination，或含未识别子容器/外部引用时，保留 Path、SrcPdu 和源链。其他目标腿及其 CanIf/EcuC 的原始语义也进入 `RETAIN` 输出复核。

HRH、TxBuffer、CanIf 控制器/硬件对象和 PduR BSW 模块配置从不进入删除候选。路由腿已不存在是幂等 WARNING；候选不唯一、语义不同或删除子树仍被引用是全局阻断错误。

## 信号 DELETE 与 LIN 定位

常规 CAN 信号继续要求 ComIPdu SHORT-NAME 中存在配置表网段标记，并通过方向、报文名前缀和 `ComIPduSignalRef` 核对信号归属。

LIN 不使用 `PSMM ↔ LIN04` 之类项目固定映射。只有常规网段定位为零，报文名+信号名+方向+`ComIPduSignalRef` 在全部 CAN/LIN 端点中唯一，且实际 ComIPdu 名称明确带 `_oLIN..._` 时才接受。多 LIN 或 CAN/LIN 同名对都阻断，不做模糊选择。

定位到源/目标 ComSignal 后，要求 Mapping 内恰好一个 ComGwSource 且其嵌套引用唯一指向源信号，再在 Mapping 内按目标 ComSignal 引用定位唯一 Destination。仍有其他 Destination 时保留 Mapping/Source/超时；无其他目标但有人工子容器或 Source 子树外部引用时，只删目标并保留源链。Destination 或其嵌套子对象仍被外部引用时阻断，避免新增悬空引用。

## 源端超时删除

超时属于源 ComSignal，不属于某个 Destination。计划以源 ComSignal 分组，一次性查看整批 Mapping 删除后的投影，避免同批已计划删除的 Mapping 互相误判为“仍存在”。只有以下条件全部满足才清理：

1. 投影中已无任何目标或其他 Mapping。
2. 本次 ADD 的实际源 ComSignal 路径集合不包含该信号。
3. 同源全部 DELETE 行的超时证据一致，且非空。
4. ARXML 中 Action 唯一为 `REPLACE`，Timeout/可选 Substitution 唯一且与 DELETE 值完全相等。

清理只涉及 `ComRxDataTimeoutAction`、`ComTimeout`、`ComRxDataTimeoutSubstitutionValue`。任一条件不满足就保留全部超时并记录原因，不删其他 ComSignal 参数。

## 输出验证

临时输出重新解析后执行：

- AUTOSAR Schema 与 CanIf、Com、EcuC、PduR 四模块完整性检查。
- `REMOVE` 对象不存在且无输出内部引用；DELETE+ADD 同路径重建例外由 CREATE 语义复核接管。
- `RETAIN` 对象仍唯一存在，对共享源/目标腿、CanIf/EcuC 和 Com Source/Destination 比较原始参数与引用。
- `REMOVE_PARAMETERS`/`UPSERT_PARAMETERS` 与计划值一致。
- ADD 对象完整语义、新引用唯一可解析、新 UUID 全局唯一、新 Handle 未复用。

历史重复 UUID/Handle 或指向外部 ARXML 的历史引用不被当作本次新问题；但删除规划会显式检查整个被删命名子树的反向引用，阻止本次引入新悬空。

## 索引与性能

初始树只建立一次 `ArxmlIndex`，四个模块编辑器共享。索引重建将 SHORT-NAME、DEFINITION-REF 和 VALUE-REF 合并到单次直接子节点扫描，并缓存已命名祖先路径。模板父容器、Handle 已用值、PduR 模块引用和 Com 超时参数模板均使用共享索引/缓存，不按每条路由扫描 81 MB 全树。

定向真实集成测试同一用例先完成 preview，再完成全量 ADD+DELETE 生成和输出复核，实测用时 35.06 s。单次真实 preview 在性能收敛阶段从 181.99 s 降至 18.29 s。

## 代码审查发现—修复—验证

1. **父容器隐式误删**：最后一个 Destination 被删时，早期方案会直接删父 Path/Mapping，可能连带未识别人工子容器。修复为检查未知直接子容器和整个命名子树反向引用；存在任一证据就只删目标腿。新增 PduR/Com 人工子容器保留回归。
2. **ComGwSource 结构歧义**：仅递归搜索源信号引用可能忽略同一 Mapping 中多个 Source。修复为要求恰好一个直接 Source，且其嵌套引用恰好一个并指向期望源信号。新增重复 Source 阻断测试。
3. **LIN 回退隐藏 CAN/LIN 同名歧义**：只在 LIN 集合内求唯一会错选 LIN。修复为对全部 CAN/LIN 的报文+信号结构对求全局唯一，再确认唯一对的 ComIPdu 是 LIN。唯一 LIN、多 LIN、CAN/LIN 同名和 LIN DELETE 回归均通过。
4. **同源多 Mapping 超时投影**：逐 Mapping 判断会把同批待删 Mapping 互相视为现存用户。修复为先确定全部可删 Mapping，再按源信号汇总证据并一次判断。新增“两 Mapping 同批删除后清超时”回归。
5. **隐式子对象悬空引用**：只检查父容器路径会漏掉 ComGwSource/Destination 内嵌 ComGwSignal 等命名子对象。修复为在规划阶段遍历待删命名子树的反向引用；目标子树被引用时阻断，源子树被引用时保留源链。补充 PduR Destination 和 Com 嵌套 Destination 引用回归。
6. **保留语义复核不足**：一对多时早期计划只记录父路径存在。修复为对保留的 PduR Src/Dest、源 CanIf/EcuC、其他目标 CanIf/EcuC 和 Com Source/Destination 生成 `RETAIN` 语义快照，输出复核中比较原参数/引用。
7. **81 MB 重复扫描**：初版真实 preview 用时 181.99 s。修复共享索引、阶段边界重建、索引单遍构建、模板缓存和基于索引的 Handle/父容器/引用查找后，单次 preview 降至 18.29 s。

审查修复后，`tests/unit/test_generate_delete.py` 37 条全部通过；DELETE/信号/CLI 相关三个文件在中间收敛点 53 条全部通过。

## 已知限制

- 直接报文只支持 CAN/CAN FD，不实现直接报文 LIN 路由。
- 信号 LIN 只引用已存在的 Com 对象，不新建或修改 LinIf；无全局唯一结构证据时必须人工处理。
- 不处理诊断、CanTp、多 ARXML 合并、原始路由表/History、DBC 自动修改、DaVinci 自动导入/Validate、GUI 和 EXE 打包。
- 缺失目标版 DBC 的 ADD 仍按路由警告跳过；DELETE 不会在缺少身份证据时猜测。
