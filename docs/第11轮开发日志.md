# 第11轮开发日志：路由组分类与错误作用域修复

## 本轮目标

本轮修复一个会严重阻断正常使用的路由组索引问题：真实基线中的应用组可能同时包含普通 CanIf 目标成员和少量完整的 Com、CanTp、DoIP 等非 CanIf 目标成员。旧逻辑采用“全组成员必须都是 CanIf”的一票否决规则，导致一个非 CanIf 成员使整个应用组失效，并把同一基线错误重复挂到几乎所有 Excel ADD 行。

E03 基线中的直接触发数据为：`PduRRoutingPathGroup_ICCanApp` 共175个成员，其中174个目标为 CanIf、1个目标为 Com。该 Com 成员引用链完整，不是悬空对象；旧版本却令 ICCAN 主组映射消失，并把同一个 `PDUR_ROUTING_GROUP_MIXED_MODULES` 错误复制到94条 ADD。

## 实现方案

### 逐成员分类

`RoutingGroupMembershipService` 现在先沿 `PduRDestPduModuleRef → PduR BswModule → PduRBswModuleRef` 判断目标模块，再处理普通 CAN 通道链：

```text
PduRDestPdu
→ EcuC PDU
→ CanIfTxPdu
→ CanIfTxBuffer
→ 引用数据中的 CAN 通道
```

- 完整 CanIf 目标成员参与主通道计数。
- 完整非 CanIf 目标成员不参与普通 CAN 通道计数，不会令同组 CanIf 成员失效，也不会被工具修改。
- 纯 CanTp、DoIP、Com 等非 CanIf 组仍不会进入普通应用组索引。
- CanIf 目标链缺失、重复、悬空或不唯一时仍保持阻断，不以本轮修复为由放宽结构安全检查。
- 部分工程不会导出 CanTp 等诊断模块本体，因此非 CanIf 分类以 PduR BswModule 的真实完整引用路径为准；目标模块存在时，再交叉确认其中确有对象引用目标 EcuC PDU。

混合组只输出一次 `PDUR_ROUTING_GROUP_NON_CANIF_MEMBERS_IGNORED` 基线提示，明确说明被排除成员、目标模块及“不影响其他 CanIf 成员”。

### 错误作用域

索引问题增加受影响通道信息：

- 主通道计数并列只阻断该组实际涉及的候选通道。
- 多个组竞争同一主通道只阻断该目标通道。
- 无法从损坏结构推导通道的问题，仅在请求通道本身也没有可用主组时展示；已经通过真实引用建立主组映射的其他通道继续处理。
- `PDUR_APPLICATION_ROUTING_GROUP_NOT_FOUND`、TxBuffer/通道不一致等请求级错误仍归属具体 Excel 行。

这使一个 ICCanApp 问题不再阻断 DACAN、GLCAN、SUCAN 等无关通道，同时保留真正相关通道的安全阻断。

### 归属、去重和提示

- 基线索引问题只归属输入 ARXML，不借用当前 Excel 行、报文身份或计划 DestPdu。
- ADD 规划、DELETE 批处理以及 DELETE/ADD 两阶段合并都按完整可见身份去重，不再只对某一个警告代码做特殊处理。
- 非主通道警告显式携带所属组自己的主通道，修复循环变量串用导致提示主通道错误的问题。
- GUI 对非 CanIf 排除提示显示“无需修改配置表；工具已排除该成员，如需确认请核对基线 ARXML”，避免用户通过不断删除需求行寻找所谓“下一条错误”。

## ADD、DELETE 与信号路由检查

- ADD：目标通道只读取与自身相关的索引阻断；混合应用组可以继续创建目标腿和成员引用。
- DELETE：继续语义定位精确 DestPdu，核对实际组和目标通道主组，再按“删除成员引用 → 删除目标腿”执行；完整非 CanIf 成员不会阻断无关删除，也不会被自动迁移。
- 信号路由：未调用路由组成员索引；本轮没有增加无关兼容逻辑。受影响模块回归包含信号 ADD/DELETE 和 Signal Access，确认没有被路由组问题提前阻断。

## 严格代码审查

本轮审查了完整未提交 diff，并沿全工程调用点检查 ADD、DELETE、事务合并、GUI DTO 展示、MCP/CLI/Facade 和输出验证。Codex 内置 Review 面板也已打开用于检查未提交变更；当前环境没有额外安装独立代码审查插件。

审查中发现并修复：

1. 首版实现曾要求所有非 CanIf 目标模块本体必须包含在导出 ARXML 中，真实 E03 因未导出部分诊断模块产生252条误报；已改为按 PduRBswModuleRef 完整路径分类，模块存在时再交叉验证。
2. 事务合并原来只对 `PDUR_ROUTING_GROUP_NON_MAIN_MEMBER` 特判去重，新提示可能在 DELETE/ADD 各出现一次；已改为全部相同可见问题统一去重。
3. 非主通道提示使用循环外遗留的 `main` 变量，多个组时可能显示错误主通道；已把主通道随异常成员一起保存。
4. 基线 ERROR 仍可能携带调用方的 Excel `SourceLocation`；基线问题构造现在强制使用空工作表位置。
5. 归属未知的损坏组仍会全局阻断已有有效映射；已调整为只在请求通道没有可用主组时展示和阻断。
6. 确认信号路由不复用路由组索引，本轮没有加入无证据的信号兼容层。

审查同时确认：生产代码没有 E03、ICCAN 或具体组名硬编码；诊断组排除依据真实模块引用；未修改路由组名称、GroupId、初始化状态及无关成员；DELETE 的成员引用删除顺序和外部引用投影保持不变。

## 已知限制

- 无法解析成员真实通道的损坏组不会污染已有有效通道，但目标通道本身缺少可用主组时仍会阻断；工具不会依据组名猜测归属。
- 完整非 CanIf 成员只从普通 CAN 通道统计排除，不会自动迁移、删除或修正其基线关系。
- GUI 心跳小于1秒的断言仍可能受当前机器负载影响；本轮未为测试时序抖动修改产品代码。
